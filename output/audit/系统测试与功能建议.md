# 远帆 ERP 测试与功能建议

日期：2026-11-03。对象：本机 `codex/independent-login` 分支的账号密码版。所有写入测试均使用内存 SQLite 和模拟业务数据，没有修改线上业务数据或真实用户密码。本报告不是线上生产环境验收；独立部署、真实多设备与长期使用仍需验收。

## 结论

基础业务链路可运行，但异常接口输入和部分账号管理事务仍有缺陷，建议先修复再正式用于业务。此次工作为测试和评估，没有把发现的问题自动修改或发布到线上。

## 已通过的回归组

1. 采购与发票：加权采购成本、重复入库拦截、发票费用及金额计算、自定义发票号保存、客户文本转义。
2. 装箱发货：混装、体积和重量汇总、发票剩余可装数量限制、毛重不小于净重、库存不足时不扣减、重复发货不重复扣减。
3. 商品包装：按 3 件/箱、2.908 kg/件、9.728 kg/箱计算，2 箱为 6 件、净重 17.448 kg、毛重 19.456 kg；尺寸带入、尾箱提示、缺包装资料拦截、备份保留包装字段。
4. PDF 导出：尺寸、净重、毛重及混装合并行均进入输出；样例汇总为 27 箱、97 件、184.20 kg 净重、206.20 kg 毛重；多页输出检查通过。此次重新执行的是渲染程序和结构断言，没有重新检查每一台设备的打印驱动。
5. 账号密码：独立盐与哈希、两个管理员映射同一主账号、子账号独立身份、无注册或验证码入口、跨站请求拦截、安全 Cookie、改密和退出使对应会话失效、停用拦截、登录限流。
6. 基础接口权限：子账号不能直接访问其他账号、不能创建账号或读取全局汇总及日志、普通修改权限检查、并发版本冲突拦截、主账号不能停用自身。

## 已复现的问题

### P1：单据类型变化存在操作权限绕过

准备一个仅允许 `quote` 的子账号，主账号事先为其数据空间放入一张 invoice。子账号把同一 ID 的单据类型从 invoice 改为 quote，通过整份状态保存接口提交。预期拒绝，实际 HTTP 200。

原因：`changedAreas()` 对同一单据变化只收集新类型权限，没有同时检查旧类型。影响限于该子账号自己的业务空间，本次未发现借此跨账号读取数据。建议既有单据的类型不可直接变更，转换必须新建单据并保留来源关联。

### P1：服务端数据及出入库一致性校验不足

下面六种状态提交均获得 HTTP 200：

- 重复商品 ID。
- 不同商品使用重复 SKU。
- 两份不同 ID 的发票使用重复发票号码。
- 发票运费为负数。
- PCS 计量的库存出现小数。
- 装箱 boxes 中装入 20 件，关联发票仅 2 件，而出库 lines 仅 1 件，仍可标记已发货并保存。

这些场景直接测试接口和导入可能到达的服务器保存入口。正常页面已有部分拦截，不能因此推断服务器安全。建议增加唯一性、金额、计量单位和关联数量校验，并将采购入库、发货扣库存作为专门的服务器事务，统一校验单据、库存和流水。

### P2：无效重置密码请求会部分生效

主账号提交对子账号的修改：停用、移除权限，同时提供一个不合要求的短密码。接口返回 HTTP 400，但账号已经停用且权限已被移除。

原因：先更新权限和启停状态，再校验密码。建议先校验所有输入，再将权限、状态、密码哈希更新及审计记录放入一致的事务。

八个异常场景的实际响应见同目录 `异常场景复现结果.json`。

## 建议补充的业务功能（按优先级）

| 顺序 | 功能 | 业务价值 |
|---|---|---|
| 先修 | 上述权限、数据校验、事务缺陷 | 防止错误数据和权限绕过 |
| 第一批 | 最新采购参考价、实际成交价、库存平均成本分开；供应商价格历史 | 应对市场价格变化，不直接改写原库存成本 |
| 第一批 | 单据草稿、确认、作废、更正版本及原因 | 错单可按流程修正，有据可查 |
| 第一批 | 自动备份与实际恢复演练；按账号导出；可回溯修改记录 | 降低误操作、部署和迁移风险 |
| 第一批 | 备用管理员重置主用管理员凭证的安全恢复流程 | 当前可用备用账号继续管理，但界面没有重置另一个管理员凭证的专门入口 |
| 第二批 | 客户、供应商资料库 | 减少重复输入地址、联系人、付款条款 |
| 第二批 | 分批采购到货、待到货数量、退货与换货 | 避免所有异常业务都靠手工改库存 |
| 第二批 | 在库、已占用、可用库存及盘点调整原因 | 避免多票待发货同时占用同一库存 |
| 第二批 | 外币采购、汇率、运费和手续费分摊 | 外币采购目前不能直接按人民币成本入库 |
| 第二批 | 收付款记录、已付/未付、应收应付 | 区分发票金额与实际收款、付款 |
| 第二批 | 物流公司、运单号、出货及签收状态 | 从装箱发出追踪到客户签收 |
| 后续 | Excel 批量导入及逐行错误提示、商品图片、条码扫描、库存龄和毛利报表 | 提高录入速度及经营分析能力 |

## 正式上线前还需验收

独立站 HTTPS 与数据库绑定；迁移真实账号数据后核对库存和已发货状态；两台设备同时修改；主用和备用管理员的恢复演练；不同浏览器的发票打印及长装箱表；大量单据和 Logo 下的保存大小及性能；备份后实际恢复。当前单账号以整份 JSON 状态保存，数据量增大后应评估拆分为商品、单据、流水等独立表，避免每次操作重写全部历史。
